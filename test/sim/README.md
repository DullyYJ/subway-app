# 탑승 시뮬레이션 (test/sim)

실제 탑승을 흉내 내 GPS를 흘려 보내고, 앱이 (1) 계획대로 갈 때 얌전한지 (2) 시각표와 다르게 움직일 때 (3) 안내한 차와 다른 차를 탔을 때 경로를 다시 찾는지 (4) 마커(앱)·오버레이가 따라가는지를 잰다.
**앱 코드는 건드리지 않는다.** 시험 쪽에서 앱 함수를 호출만 한다.

## 실행

    node test/sim/ride_sim.js --list                      # 시나리오 목록(116개)
    node test/sim/ride_sim.js --filter "^bus/faithful"    # 일부만
    node test/sim/ride_sim.js --shard 0/2 --out a.json    # 절반씩 나눠 두 프로세스로(전체 약 1시간)
    node test/sim/summarize.js a.json b.json > summary.md # 표로 요약

난수 시드는 시나리오 id 로 고정이라 같은 코드·같은 앱이면 같은 값이 나온다. 느려서(시나리오당 30~100초) CI 매트릭스에는 넣지 않았다.

## 세계 (world.js)

- 출발 O=(0,0), 도착 D=(동쪽 7km). 앱이 마지막 노드를 검색 좌표('수원')에 놓기 때문에, 출발점을 그 좌표에서 서쪽 7km 로 잡았다.
- 계획 구성 5가지: bus(88번, 정류장 14개, 450m/90초) · sub(1호선 7역, 1000m/150초, 지하) · bus_sub · sub_sub · sub_bus.
- 엔진 모의(makeEngine): 첫 탐색은 계획 경로 + 후보로 급행97(북쪽으로 불룩한 다른 버스). 이후 탐색은 요청한 출발 위치에서 도착지까지 직진 버스(도보 1분 + 버스 + 도보 3분).
- 열차·버스 실시간 위치 API 는 없는 상태(GPS 와 시각표만).

## 행동 (ride_sim.js)

| 행동 | 내용 |
|---|---|
| faithful | 계획대로 탑승. offset(초)로 차량이 시각표보다 늦거나(+) 빠름(−) |
| alt_vehicle | 같은 출발·도착, 엔진이 후보로 준 다른 버스(급행97)를 탐 |
| unknown_vehicle | 엔진이 모르는 버스(남쪽으로 불룩)를 탐 |
| taxi | 정류장 없이 빠르게, 엔진이 모르는 길 |
| wrong_dir | 반대(서쪽) 방향 차를 탐 |
| strange_place | 계획 차를 타다 4번째 정류장에서 내려 북쪽 1.5km 로 걸어감 |
| skip_transfer | 환승역에서 내리지 않고 같은 차를 3정류장 더 탐(관찰만) |
| stay_home | 타지 않고 집(서쪽)으로 돌아감 |
| walk_along | 놓치고 노선을 따라 걸어감 |

변수: 계획 구성 5 × 소음(clean: 8m, noisy: 40m 흔들림 + 3% 는 250m 튄 점) × 차량 지연(−60/0/+240/+480초) × 위치상태머신 입력(asis/wired).
`wired` 는 대조군이다. 앱의 위치 상태머신(LOCFSM)은 현재 승차 대기 틱에서만 GPS 를 받는다(index.html 7630). wired 는 시험이 `locOnGps` 를 매 틱 불러 "백그라운드 GPS 도 들어간다면" 어떻게 되는지를 본다.

## 측정

- 마커 오차: 앱이 그린 마커(`_markerPos` 두 노드 사이 보간)와 실제 위치의 거리.
- 오버레이 오차: 오버레이가 가리킨 칸(현재 정류장)의 좌표와 실제 위치의 거리. 칸 단위라 정류장 간격만큼은 정상이다. '도보' 칸은 노드를 특정할 수 없어 뺀다.
- 재탐색: route-v2-app 요청이 새 출발 좌표로 나갔는지. 재탐색 출발 위치 오차·같은 도착지 여부·이탈 후 걸린 시간.
- 경로맞춤: 앱이 엔진 후보 중 실제로 탄 경로를 골라 이어서 안내(`_matchRiddenRoute`)한 횟수.
- 오버레이 켜짐: 오버레이에 보낸 마지막 상태가 active 인 비율.

## 한계

- 합성 지형(직선 노선)과 모의 엔진이다. 실제 도로·노선 겹침·실시간 데이터는 없다.
- 판정 기준(마커 600m 등)은 이 시험을 위해 정한 값이다. FAIL 은 "앱 버그"가 아니라 "기대와 달랐다"는 뜻이니 RESULTS_2026-10-12.md 의 해석을 같이 본다.
- 지하는 GPS 를 아예 끊어 흉내 냈다(실기기에서는 튀는 좌표가 남을 수 있다).
